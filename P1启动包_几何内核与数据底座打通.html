文档定位：本启动包是《建设规划方案 v1.5》P1 期的细化执行版。规划方案已于 P0 阶段完成立项评审材料（规划方案 / 基线文档 / 评审 PPTX）。本包在 P0 评审通过、6 项待确认项中 P1 前置项拍板后，即可作为开工依据。文中标注 门禁 的条目为 P1 开工前必须先决议的事项。

P1 是"从纸面到孪生"的第一道工程关口：把规划方案里的两个已确定构件——华为 OGG 几何内核（锁定）与实时数据底座（待定选型）——真正部署、打通，并产出"几何保真 + 同步保真"最小闭环 Demo，作为 P2（仿真 + 智能层）接入的底座。

本包不解决但需衔接的事项：CAE 仿真（P2）、解耦 Agent 智能层（P2）、模型验证体系（P3）均在后续期次。P1 仅须为它们预留标准化接口契约（几何模型接口、实时数据流接口、通用 MAS 接口占位），不做实现。

五、构件 A：OGG 几何建模链路落地

5.1 部署与工程化

  • 获取与合规：OGG 源码托管于 Gitee（gitee.com/opengeometry，非 GitHub），已开源可直接获取：注册免费 Gitee 账号即可 clone / 下载 ZIP，无审批环节；许可证为 LGPL 2.1（继承自 OCCT，非 BSD）。页面\"公测招募\"是参与华为 486 项增强特性早期验证的志愿计划（可选），非获取基础代码门槛。获取后内部镜像归档，避免外部依赖。注意：GitHub 上的 OpenGeometry-io（Rust→WASM 浏览器 CAD 内核，MPL-2.0）是同名不同源项目，切勿混淆。
  • 容器化部署：以 Linux 容器封装 OGG 运行时 + 依赖（几何内核编译工具链、Python/C++ 绑定）；纳入 CI 流水线，保证可复现构建。
  • CAD 数据交换：打通 STEP / IGES / STL / OBJ 导入导出，建立与 PLM（产品生命周期管理）系统的对接通道，承接装备/产线原始几何。

5.2 OCCT 兼容验证清单

验证项方法通过判据
拓扑一致性同一 BREP 模型分别在 OGG 与 OCCT 重建，比对边/面/体数量拓扑等价，无破面/冗余
几何精度关键尺寸（公差特征）在原 CAD、OGG、OCCT 三者间比对偏差 ≤ 0.5mm（标尺）
格式往返STEP 导出 → 再导入，检查信息损失无拓扑/属性丢失
性能中等复杂度装配体建模/布尔运算耗时满足实时交互基线
为何保留 OCCT 退路：OGG 仍处生态早期，若个别几何算子稳定性不足，可经 OCCT 兜底再转 OGG 渲染。该双内核策略已在规划方案选型章节约定，P1 须实测验证切换成本。

六、构件 B：实时数据底座

6.1 选型对照

候选路线组成适配度取舍
开源自建路线
无云默认		EMQX（MQTT）+ Apache IoTDB / TDengine + Flink高自主可控、成本可控、无需公有云；工程量略大，但契合数据不出域与自主可控
OPC UA 直采路线
无云		边缘网关（OPC UA / Modbus）+ 轻量流处理中贴合车间设备、无需上云；需补充上层时序与可视化
华为云 IoT 路线
需上云		IoTDA + 规则引擎 + 时序库（DMS/InfluxDB）视情况仅当 P0 明确采用公有云部署时采用；与华为云生态协同好，但引入云依赖
无云即可推进：默认走开源自建路线（EMQX + IoTDB，无需公有云）或 OPC UA 直采（边缘，无需上云）；华为云 IoT 仅当 P0 明确采用公有云部署时才采用。因此"部署模式=上云"不再是 P1 开工前提——无云方案下 W1 几何链路与 W2-W3 数据底座均可正常推进。

6.2 边缘采集与同步架构

物理实体 →（OPC UA / MQTT 边缘网关）→ 流处理（过滤/对齐）→ 时序库 → 孪生体几何模型增量更新 → 可视化呈现。关键机制：

  • 统一标识：设备/部件赋予全局唯一 ID，并与 OGG 几何模型树节点绑定，确保"数据 → 几何"精确映射。
  • 时钟对齐：边缘侧打时间戳，流处理层做乱序与迟到补偿，保障同步延迟 ≤200ms。
  • 增量更新：孪生体仅更新变化部件的状态/位姿，避免全量重绘，支撑实时交互。

预算（人力/授权）阻塞门禁决定团队扩编节奏与商业组件采购

POC 范围（仿真引擎）弱相关属 P2 预研，P1 预留接口即可

十一、协作与开发规范

  • 代码与文档：Git 仓库 + 特性分支策略；本启动包、周报、接口契约文档统一沉淀。
  • 接口契约优先：五元构件以标准化接口连接——OGG 几何模型接口 / 实时数据流接口 / 通用 MAS（多智能体系统）接口。AI 层先以通用 MAS 占位，不提早绑定厂商（呼应规划方案 v1.5 原则）。
  • 评审节奏：每周站会 + 双周技术评审 + 月度进展报告；M1 为正式阶段评审门。
  • 数据与合规：全程使用脱敏/样例数据；涉及车间实时数据须满足等保与数据不出域要求。

十二、下一步（触发 P2 条件）

M1 评审门通过后，即触发 P2：接入 CAE 求解器（仿真保真）与解耦 Agent 智能层（智能保真），并用规划方案附录 C 的 POC 结论确定工厂级仿真引擎选型（Plant Simulation vs AnyLogic）。P1 预留的接口契约将在此刻复用，降低集成成本。

闭环原则回顾：先以 OGG（几何保真）+ 数据底座（同步保真）把"骨架"立起来，再依次挂上仿真、智能、验证三层。P1 是整条链路能否立住的第一道硬关口。
