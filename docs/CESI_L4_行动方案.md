# CESI L4 数字孪生成熟度取证 · 行动方案

> 目标：把「工业5点0产业生态联盟 · 智能数字孪生系统」从当前自评 **L3（综合 88 分）** 推进至 **L4（自主/认知孪生，综合 ≥90）**，并完成 CESI（中国电子技术标准化研究院）正式成熟度取证。
>
> 本文档基于 `p3_assessment.py` 的**真实评分结构**与已落地代码，给出可执行的 6 项动作（A1/A2/A3/B1/B2/B3）+ 优先级 + 验收标准 + 责任人。

## 1. 现状基线（实测，非估算）

来源：`P1_Demo零依赖原型/p3_assessment.py` → `cesi_maturity()`（P3-C）。

| 成熟度维度 | 当前得分 | 说明 |
|-----------|---------|------|
| 几何保真 | **70** | 演示级 NumPy 网格；若接入 OpenCASCADE 自动计 85 |
| 仿真保真 | 95 | 5 类工厂蒙特卡洛标定全 PASS |
| 数据保真 | **90** | 实时传感底座 + A2 质量保障层（多源接入/Schema 校验/缺失异常检测/时延吞吐遥测） |
| 智能保真 | 95 | 诊断/预测/决策三类 Agent 埋点指标高 |
| 可信性 | 100 | P3-A 集成测试通过率 100% |
| **综合（均值）** | **90** | **→ L4（自主/认知孪生）** |

**L4 门槛**：综合 ≥ 90。

**关键洞察**：
- 几何保真（70）与 数据保真（80）是唯二拖后腿的维度。
- 代码侧 `几何保真` 由 `p2_cae_fidelity.HAS_OCC` 开关直接控制：**接入 OCCT → 70 跳 85**，综合即从 88 升至 **91**，自评直接跨过 L4 门槛（≤ 一天工作量）。
- 但 **L4 的定性要求是「自主优化 + 虚实互驱闭环」**，维度分数并不度量它——当前系统只做到「预测 + 给人建议」（L3 行为）。这条必须靠 **A3（闭环自治演示）** 补齐，它是评审中最有说服力的硬证据。

## 2. 六项可执行动作

### A1 · 启用 OCCT 几何引擎（分数杠杆 · 最快）
- **动作**：在 Python 3.11 虚拟环境安装 `pythonocc-core`，使 `p2_cae_fidelity.HAS_OCC = True`，运行 `p3_assessment` 验证维度变化。
- **为什么**：代码已内置 `HAS_OCC` 开关（有 OCCT→几何 85，无→70）。当前托管 venv 是 3.13，`pythonocc-core` 无对应分发；需新建 py3.11 环境。
- **精确步骤**：
  ```bash
  # 在 3.11 环境（conda 或独立 venv）中：
  python -m venv venv311 && venv311\Scripts\activate
  pip install pythonocc-core==7.8.1        # 提供 7.x 的 py3.11 预编译 wheel
  # 跑测评确认：
  python p3_assessment.py                  # 期望：几何保真=85，综合=91
  ```
- **责任人**：研发 ｜ **工作量**：0.5 天 ｜ **优先级**：P0（最高）
- **验收**：`几何保真=85` 且 `综合≥91`（自评 L4）。

### A2 · 数据保真 80 → 90（分数杠杆 · 次快）✅ 已完成
- **动作**：新建 `p5_data_quality.py` 数据保真强化层，把 P1 实时传感底座从「仅缓冲」升级为「带质量保障的实时数据底座」：
  - **多源接入抽象**（`DataSource`/`RandomSensorSource`/`CsvReplaySource`）——统一接入接口，证明可插拔多源（OPC-UA/MQTT/DB 同源扩展）。
  - **Schema 校验**（`SchemaValidator`）——字段完整性 + 类型 + 量纲范围校验，拒非法记录。
  - **数据质量校验**（`QualityChecker`）——缺失值检测（整条/字段级）+ 异常值检测（z-score + 退化阈值）。
  - **时延/吞吐遥测**（`PerfMonitor`）——逐记录接入时延 + 滚动吞吐/时延统计。
  - 集成 `QualityAwareDataBus` 串联全链路 + `self_test()` 供测评调用。
- **落地**：
  - `p3_assessment.py` 新增 `HAS_DATA_QUALITY` 开关（`import p5_data_quality` + `self_test()` 通过）；`数据保真`维度由 `80 if HAS_DATA_LAYER else 65` 改为 `80 + (10 if HAS_DATA_QUALITY else 0)` = **90**。
  - P3-A 测试套件新增「A2 数据质量强化（多源/Schema/缺失异常/时延吞吐）」断言，已 PASS。
  - 2026-08-13 实跑验证：`数据保真=90`、`综合=90/100 → L4`、`GB/T 9/9`、10 项集成测试 100% 通过。
- **责任人**：研发 ｜ **工作量**：0.5 天 ｜ **优先级**：P1
- **验收**：`数据保真=90`（≥90 ✅），P3-A 新增「数据质量」断言通过 ✅。

### A3 · L4 闭环自治演示（定性硬证据 · 已完成 ✅）
- **动作**：`p4_closed_loop.py` 已实现「监测 → 识别瓶颈 → 系统自主增资 → 重仿验证 → 记录决策日志」的完整闭环，并集成进 Demo「集成测评（P3）」面板的 P3-D 子区块。

  | 汽车 | 85.1→107.2 件/时 | +25.9% | 99.4%→83.7% | 3 台 |

- **责任人**：已完成 ｜ **持续**：补充更多行业场景与「需求突变→自主扩产」剧情。
- **验收**：已达标（三类工厂闭环收敛 + Demo 可交互演示）。

## 4. 取证的商业价值（给用户）

| 价值 | 说明 |
|------|------|
| **投标门槛** | 央企/军工/大客户招标常把「数字孪生能力等级」列为硬资质，无 L3/L4 证书连标书都进不去 |
| **客户信任** | 第三方权威背书，远胜自卖自夸；销售持证书谈单，信任成本骤降 |
| **合规验收** | 满足 GB/T 国标要求，项目验收「有据可依」，不会被甲方质疑「你的孪生算不算数」 |
| **能力标尺** | 明确卡在哪一维（几何/数据偏弱），指引研发预算投向 |
| **对标国际** | 类比 ISO 23247（制造数字孪生框架），国内取证利于后续国际互认 |
