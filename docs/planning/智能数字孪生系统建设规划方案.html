一、执行摘要

一页纸结论

方向
采用"华为 OGG（几何内核，锁定）+ 解耦 Agent 智能层（厂商无关、按指标选型）+ 仿真保真层（装备 CAE + 工厂级仿真）+ 实时数据底座 + 模型验证体系"架构，构建自主可控、覆盖"装备—车间—工厂"的高保真智能数字孪生系统。技术可行，标准适配度高。
建设路径
建议分 4 期 / 约 18 个月推进：P0 立项与标准基线 → P1 几何内核与数据底座打通 → P2 仿真保真与智能层接入 → P3 系统集成、验证与测评认证。每期设硬交付物与里程碑评审门。
合规
"高保真"符合性不以组件判定，而由最终交付的系统通过 GB/T 43441 系列 / GB/T 45626-2025 设计与 CESI 成熟度测试 / 可信性测评认证来证明。规划中将保真指标写入验收基线。
关键前提
OGG 解决几何保真、解耦 Agent 解决智能保真；但仿真保真（装备 CAE + 工厂级生产系统仿真）、同步保真（IoT）、验证保真（建模验证流程）三块必须补齐，单靠 OGG+Agent 达不到国标"高保真"门槛。

2.2 建设必要性

① 政策牵引。《国家智能制造标准体系建设指南（2024版）》已将数字孪生列为独立标准子体系；装备/车间数字孪生国标于 2025 年密集落地，进入"有标可依、按标验收"阶段，先行建设可抢占招投标与示范项目窗口。
② 自主可控诉求。几何内核是工业软件"根技术"。采用华为 OGG（LGPL 2.1 开源、国产替代 OCCT）作为几何保真锚点，规避对法国 OCCT / 西门子 Parasolid / 达索 CGM 的底层依赖，符合供应链安全要求。
③ 业务价值。高保真孪生可支撑预测性维护、工艺仿真优化、虚拟调试、远程运维，直接降低停机损失与试错成本，是装备/制造企业数字化升级的核心基础设施。
④ 智能层解耦红利。AI 大模型半年一迭代，智能层保持厂商无关、按指标选型，既保障合规（国标不看厂商），又避免把变化最快的 AI 层焊死在单一云厂商。
⑤ 工厂级仿真诉求。装备/线级孪生解决"单机最优"，工厂级生产系统仿真（布局/物流/排程/产能）解决"全局最优"，可支撑新建工厂虚拟验证、产能爬坡推演与供应链协同，是数字化工厂从"点"到"面"的关键跃迁，也是 GB/T 45873 车间/工厂孪生的核心能力。新建厂虚拟验证与存量产能优化两类场景并重。

三、总体目标与建设原则

3.1 总体目标

建成一套自主可控、高保真、可认证的智能数字孪生系统，满足 GB/T 43441 / GB/T 45626-2025 / GB/T 45873-2025 核心技术要求，具备装备级物理仿真与工厂级生产系统仿真双重能力，通过 CESI 成熟度或可信性测评，达到"高保真"二级及以上等级，并在至少 1 个标杆装备/产线场景与工厂级仿真场景（覆盖新建厂验证与存量产能优化两类）完成闭环验证与商业落地。

3.3 建设原则

自主可控几何内核锚定国产、智能层开放选优；通用接口Agent 层采用通用 MAS 接口标准，不与厂商/框架绑定，先闭环后个性化；标准先行架构对标 GB/T、验收按测评；闭环可信建模型验证流程、虚实验证留痕；分期交付每期有硬交付物与评审门；解耦可替换五元构件接口标准化、可单独升级。

四、总体架构设计

4.1 五元分层架构

图例：实线蓝框=锁定件（OGG 几何内核）；虚线蓝框=解耦件（Agent 智能层，厂商无关可替换）；灰色虚线框=需补齐/需自建件（装备 CAE + 工厂级仿真、实时数据底座、模型验证）；灰色虚线箭头=受国标约束的合规对齐关系。③仿真保真层一并覆盖"装备级物理仿真"与"工厂级生产系统仿真"两类。

4.2 数据流与闭环

物理实体 →（④实时数据底座采集/同步）→ ①OGG 几何模型 + ③装备 CAE / 工厂级仿真模型 ←（⑤模型验证体系虚实对照标定）→ ②解耦 Agent 层分析预测/故障诊断/决策优化 →（④反馈控制）→ 物理实体。五元件通过标准化接口契约连接，任一构件可独立升级替换，避免锁定。

五、关键技术选型

层推荐选型选型理由与边界
① 几何内核
几何保真		华为 OGG（锁定）
保留 OCCT 兼容退路		LGPL 2.1 开源、国产替代 OCCT；提供曲面/实体建模、CAD 交换、可视化。极端工况/超大装配需做成熟度验证。不含物理仿真。
② Agent 智能层
智能保真		厂商无关：国产 LLM（ GLM / 通义 / DeepSeek）+ 开源框架（LangGraph / AutoGen / CrewAI）；接口采用通用 MAS（多智能体系统）标准满足 GB/T 45626 故障诊断(6.4)/状态预测(6.5) 与可信性预测/操控精度即可；华为 Agent 作参考范式而非强制。Agent 间及对外接口统一用通用 MAS 协议，不与特定框架/厂商绑定，避免锁定；不自建厂商锁定，也不将国产替代列为 P0 验收硬指标——深度自主可控作为闭环后的个性化迭代项。
③ 仿真保真层
仿真保真		装备 CAE（国产 Simdroid / 开源 CalculiX·Code_Aster）+ OGG 几何驱动；工厂级仿真引擎（离散事件·物流·产能·排程，如 Plant Simulation·AnyLogic 或国产替代）装备 CAE 承担 GB/T 45626 仿真(6.1) 物理机理；工厂级仿真引擎承担车间/工厂生产系统仿真（GB/T 45873），覆盖布局/物流/排程/产能。两者共同构成"仿真保真"，是"高保真"核心。
④ 实时数据底座
同步保真		华为云 IoT 数据分析（DTML + 十万级并发）或自选型边缘时序平台承担 GB/T 43441 "适当速率和精度同步"；毫秒级采集、双向映射、边缘预处理。选型受等保/数据不出域约束。
⑤ 模型验证体系
验证保真		自建流程 + CESI 测评工具链落实 GB/T 45626 模型验证(7.3)/虚实验证与评估(7.5)；提供"虚对实"可信映射证据，是合规关键。

    几何与布局厂房/产线布局图（CAD/IFC/BIM）：面积、柱距、物流通道、设备占位现有布局 CAD + 实测工位坐标与通道实测设计院 / 工厂工程部；② 现场实测① 开工前设计文档（时点早、风险低）；② + 实测校准
    工艺与产品工艺流程图（PFD）、工序定义、装配层级现行工艺路线 + 历史 BOM 与产品变型工艺部门 / PLM① 设计版；② 现行版 + 变型清单
    节拍与周期设计节拍 Takt / 目标 CT、工序时间标准实测 CT、OEE、瓶颈工序历史（≥6–12 月）② MES / SCADA② 历史运行数据，需含异常与停机标注
    设备与资源设备选型参数（占地、节拍、可用率、故障率假设）在用设备台账 + 实时状态 + 停机/故障记录② 设备管理系统 / SCADA② 台账 + 实时接口（停机需根因分类）
    物流与仓储物流路径设计、AGV/叉车策略、仓储与齐套策略现有物流节拍、齐套率、在制品（WIP）水平② WMS / MES② 历史 + 实时，瓶颈工位需标注
    生产与订单目标产能 / 年产量、产品组合与混线比例订单波动、排产约束、APS/MES 排程规则② ERP / APS② 历史 12 月 + 实时订单接口
    仿真模型输入布局/物流/排程假设参数集（可变更的"what-if"变量）历史产能基线、瓶颈诊断结论（仿真校验基准）仿真引擎输入P2 建模前冻结版本，纳入配置管理

    采集要点：场景①多为设计文档，开工前即可获取、风险低；场景②强依赖历史运行数据与 MES/ERP/SCADA 实时接口，数据粒度与质量是仿真可信度的关键（对应第九章"工厂级仿真数据粒度不足"风险），须在 P1 即规划采集链路与清洗规则。

    B.2 工厂级仿真引擎（离散事件 / 生产系统仿真 · 对应 GB/T 45873）

    名称性质强项自主可控度与数据底座集成 / 备注

    AnyLogic商业（国外）离散事件+系统动力学+Agent 多方法低复杂物流/供应链协同场景适配性强

    国产 MES 仿真模块国产轻量排程/产能仿真中与 MES 绑定，能力有限但可控
    选型小结：① 装备 CAE 国产替代已较成熟（Simdroid / 中望 / PERA SIM 可为主力），自主可控主线清晰；② 工厂级离散事件仿真国产成熟商业引擎稀缺，是当前自主可控的薄弱点。建议采用"商业引擎保功能（Plant Simulation / AnyLogic）+ 同步评估国产 MES 仿真模块 + 长期基于 SimPy / 开源框架自研轻量引擎"的三段路线，并把仿真引擎接口标准化（模型导入/结果导出契约），以便后续国产替代替换、避免锁定。

    附录C · 工厂级仿真引擎 POC 验证大纲（P0 阶段 · 2–3 周）

    本大纲支撑 P0 选型决策：在正式采购前，用最小成本验证 Plant Simulation 与 AnyLogic（附录B 候选短名单的商业主力）哪个更贴合本项目的"新建厂验证 + 存量产能优化"双场景，并初步判断国产替代（SimPy / 国产 MES 模块）的长期可行性。产出写入 P0《需求规格与标准符合性基线》的选型决策记录。

    C.1 POC 范围与边界

    不做全厂建模，只做"代表性切片"：① 新建厂场景取一条代表性产线 / 一个车间做布局 + 物流验证；② 存量场景取当前瓶颈工段做产能爬坡 / 排程推演。周期 2–3 周、投入 1 名仿真工程师 + 0.5 名数据工程师。目标是验证"能力与贴合度"，非精度达标（精度在 P2 正式建模阶段用真实数据标定）。

    C.3 POC 任务分解（2–3 周节奏）

  • 第 1 周 · 数据准备与环境搭建。按附录A 取"最小切片"数据（样例 / 脱敏）；申请两引擎试用许可；搭建建模与数据对接环境。
  • 第 2 周 · 场景①对比建模。同一代表产线在两引擎各重建一遍，对比建模效率、布局瓶颈输出一致性、3D 可视化效果。
  • 第 3 周 · 场景②对比建模 + 决策。用存量瓶颈工段样例数据（含 MES 接口对接验证）做产能 / 排程推演；完成决策矩阵打分；输出《POC 验证报告》与选型建议（资源充足可压缩至 2 周）。

    • C.4 验收 / 判定标准

    判定项通过标准
    场景①可达性两引擎均能在 ≤X 人天内重建代表产线，布局瓶颈报告结论一致
    场景②数据接口能接入样例 MES 数据（CSV / API），输出产能 / 瓶颈对比，与历史基线偏差可接受
    可视化与汇报输出物可用于方案评审汇报（3D / 动态）
    选型结论按加权矩阵 + 国产替代可行性，给出首选推荐并写入 P0 基线

    C.5 国产替代评估（闭环后个性化候选 · 非 POC 必做）

    通用 MAS 接口已保障 Agent / 仿真引擎的解耦与可替换性。国产替代（SimPy 开源自研轻量引擎、国产 MES 仿真模块）不列入 P0 / POC 必做项，可作为系统闭环后的个性化迭代候选：待双场景跑通、接口契约稳定后，再评估用开源/国产引擎替换商业引擎的可行性，以平滑控制自主可控节奏、不影响主线交付。

    POC 合规注意：① 全程使用脱敏 / 样例数据，避免等保与数据不出域问题；② 商业引擎试用许可需在期限内完成验证；③ POC 目标为"验证能力与贴合度"而非精度达标，精度在 P2 正式建模阶段用真实数据标定。
